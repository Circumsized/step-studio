## 阻塞变更记录（2026-11-13 实查）

**M5.2 的更新流程从「缺接线」改判为「缺 HTTP 客户端」**——这不是接线问题。

壳侧要完成 check（拉索引 → 验签 → 比版本 → 提示）需要发 HTTPS 请求。查证：

- 树里有 `hyper`，但它是 wry/tao 的传递依赖，不是壳能直接用的稳定 API
- 没有 `reqwest` / `tauri-plugin-http`
- 加 `reqwest` 约 40 个传递包，且要把整套 `fetchUpdateIndex` 的拉取-验签逻辑
  （readBounded / AbortSignal / mirror / canary 发现）移植到 Rust

**判断：记缺口，不硬造。** 更新是发布面功能，不是壳的核心；为一个尚未有发布源的
功能引入 40 个包不划算。方案 §12.4 的更新验收本身也要求真机（「升级中 daemon 在跑、
降级攻击、迁移后凭据可用、回滚后数据完好，各一个真机用例」），卡 B1。

**已就绪的部分**（等 HTTP 客户端即可接线）：`swap.rs`（换包）、`upgrade.rs`（升级标记）、
`update-index.ts` 的索引解析与验签逻辑（可作为 Rust 移植的参照）、`signing.rs` 的单产物签名。
