## 附：Agent Hub 活动 pill 是一个没有生产者的字段（2026-11-15）

`AgentHub.tsx` 的 `activityPill` 读 `HubAgent.activity` 与 `currentTool` 来选
「工具执行中 · <名字>」/「等待输入」/「失败」三种 pill，但 `toHubAgent`
（581-641）**从来不写这两个字段**——唯一的写者是 `fromPreviewAgent`（695/697），
数据来自 fixture。于是每个真实运行中的 agent 都落到「思考中」兜底，
而代码看起来是支持工具级 pill 的。

专家复核（`ecc:code-explorer`）纠正了两处我事先的判断，都记下来：

1. **`activity` / `currentTool` 在整个链路里没有生产者**，不只是 Hub 这一层。
   `grep currentTool` 过 `omp-patch/overlay/` 零命中；`activity` 只以
   `ref.activity → assignment` 出现（`agent-hub-service.ts:833`）。也就是说
   `toolMeta.ts::saPill` 的 `activity === "tool" || currentTool` 分支（1084-1086）
   **同样不可达**——它比 Hub 深一层，但同一类问题。
2. **`stage` 是有生产者的**（我此前 grep 结论错了）。跑着 task job 的活 agent 有
   `taskJobProgress`（`job-service.ts:69-91` 读 `job.latestDetails.progress[].stage`），
   经 `studio-host-mode.ts:878-883` 接到 `agent-hub-service.ts:841`。它是一句
   自由文本（「checking packages/client (3/4)」「对比 pi-mermaid 类型签名」），
   不是工具名。

**处理：删掉假字段，不接 `stage` 充当工具名。**

- `activityPill` 的 `running` 收敛为「思考中」、`idle` 收敛为「空闲」，
  三个死分支删除；`HubAgent.activity` / `currentTool`、`fromPreviewAgent` 的写值、
  fixture 的字段一并删除（`waitingPrompt` 同属无生产者，一起删）。
- 「Current」区的 `currentTool` 行删除；空态文案从「无进行中的工具调用」改为「暂无」——
  前者是 Host 从不发布的信息，是一个伪造的否定断言。
- **没有**把 `stage` 喂进 `activity === "tool"` 的标签：那会渲染出
  「Running Tool · checking packages/client (3/4)」，把一个完成度探针的句子
  冒充成工具名。`AgentStage`（1118-1126）已经在两处渲染 `stage` + 完成度环，
  那才是 `design/m41-signoff.md:132` 记的参考「当前动作 + 目标文件」行的诚实对应物。
- `toolMeta.ts` 的 `saPill` **不动**：它解析的是真实存在的 Task 记录帧，
  属于信任边界上的防御性解析，Runtime 真开始发这些键时会自己亮。
  `SubagentMetrics.applyLiveSubagentRoster` 有意保留这两个字段（133-134/155-156），
  也不动。

跳过：把 Hub 接到 `collectAgents`。专家论证这不只更大，而且**修不了任何可见问题**——
Runtime 从不往 Task progress 行里写 `activity`/`currentTool`，接过去还是一屏「思考中」。
等 Runtime 真发这些键时再做，那也是 `saPill` 的工具分支唯一会亮的条件。
